## 7. MCPが受け持つ範囲を理解する

**55-70分 | ノートブック：What MCP changes**

### 手順26. 構成要素を整理する

```text
Student -> Python host <-> OpenAI model service
                |
         MCP client in the host
                |
      initialize / tools/list / tools/call
                |
         Weather MCP server
                |
       SerpApi (live weather only)
```

| 構成要素 | 本講座での役割 |
|---|---|
| ホスト（Host） | 会話、モデルへのアクセス、検証、実行回数の上限を管理する |
| MCPクライアント | ホストとサーバーを接続し、プロトコルの要求を送る |
| MCPサーバー | 天気ツールの情報を公開し、その実装を実行する |
| 提供元のAPI | ライブモードで外部の天気検索データを提供する |

### 手順27. 実行前のツール検出を追う

クライアントはセッションを初期化し、`tools/list` を要求します。サーバーはツール名、説明、入力スキーマを公開します。ホストはそのスキーマをモデル用のツール形式に変換します。その後、クライアントが要求された引数を指定して `tools/call` を送ります。

サーバーとクライアントは標準入出力、つまり **stdio** で通信します。両者は同じColabランタイム内のプロセスです。サーバーの標準出力はプロトコルメッセージ専用です。通常のデバッグ用print文をここへ出すと、通信を壊すおそれがあります。

### 手順28. 変わる点と変わらない点を説明する

演習2では、ホストがスキーマを定義して関数を直接呼び出しました。演習3では、ホストがスキーマを検出し、MCP経由で実行を要求します。天気アダプターはそのまま存在し、サーバーの内側で動きます。モデルとの会話は引き続きホストが管理します。

### ライブ天気取得の手順（任意）

1. Colab Secretsに `SERPAPI_KEY` を追加し、ノートブックからのアクセスを有効にします。
2. Preparation Cを再実行して、ランタイムに認証情報を読み込ませます。

4. セルを1回実行します。APIを直接呼び出し、OpenAIが有効ならMCPエージェントも実行します。
5. 場所、気温、単位、観測情報のラベル、情報源を確認します。デモ後は、意図しない繰り返し呼び出しを防ぐため、フラグを `False` に戻します。

ライブ要求は提供元の利用枠を消費し、OpenAI推論はAPI利用を伴います。検索結果に天気のanswer boxが含まれない場合もあります。推測値で補わず、取得できなかったことを説明してください。SerpApiはGoogleの天気検索結果を返します。元の情報提供者名は、結果内に明記されている場合のみ示します。取得時刻と観測時刻は同じではありません。

### 最初に失敗した箇所から切り分ける

| 症状 | 次に行うこと |
|---|---|
| `LAB`、`run_lab`、`PYTHON` が未定義 | Preparation A、B、C、Dを順に実行する |
| パッケージの読み込み／導入に失敗 | Bを再実行し、導入に失敗したら講師に相談する |
| キー追加後もOpenAIモードにならない | シークレットへのアクセスを有効にしてCを再実行する |
| モデルの認証／利用枠エラー | 画面共有を避けてアカウントとキーを確認し、解決しなければ代替モードへ移る |
| モデルが見つからない | モデルIDとアクセス権を講師に確認してもらう |
| MCP起動／ツール検出のエラー | Dを再実行し、モデル推論の前に準備状態を確認する |
| 利用できる天気結果がない | 都市・国と返されたエラーを確認し、推測で補わない |
| ランタイムが置き換わった／切断された | 再接続して準備をやり直し、保存済みノートブックからメモを復元する |
