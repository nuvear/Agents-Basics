## 7. 理解MCP负责的通信边界

**55-70分钟 | 笔记本：What MCP changes**

### 步骤26. 梳理系统组成

```text
Student -> Python host <-> OpenAI model service
                |
         MCP client in the host
                |
      initialize / tools/list / tools/call
                |
         Weather MCP server
                |
       SerpApi (live weather only)
```

| 组件 | 在本课程中的职责 |
|---|---|
| 宿主（Host） | 管理会话、模型访问、验证和执行次数上限 |
| MCP客户端 | 将宿主连接到服务器，并发送协议请求 |
| MCP服务器 | 公布天气工具信息，执行工具实现 |
| 服务提供方API | 在实时模式下提供外部天气搜索数据 |

### 步骤27. 先看工具发现，再看执行

客户端先初始化会话，再请求 `tools/list`。服务器公布工具名称、说明和输入schema。宿主将该schema转换为模型所需的工具格式。之后，客户端携带请求参数发送 `tools/call`。

服务器与客户端通过标准输入／输出，即 **stdio** 通信。它们是同一Colab运行时内的不同进程。服务器的标准输出专用于协议消息；普通调试print输出如果写到这里，可能破坏通信。

### 步骤28. 说明哪些变了、哪些没变

实验2由宿主定义schema，并直接调用函数。实验3由宿主发现schema，再通过MCP请求执行。天气适配器仍然存在，只是移到了服务器内部。模型会话仍由宿主管理。

### 可选的实时天气操作

1. 在Colab Secrets中添加 `SERPAPI_KEY`，并允许笔记本访问。
2. 重新运行Preparation C，让运行时读取这项凭据。
3. 在可选实时演示单元格中，将 `RUN_LIVE_WEATHER` 改为 `True`。
4. 运行一次该单元格。它会直接调用API；如果已启用OpenAI，还会运行MCP智能体。
5. 检查地点、气温、单位、观测信息标签和来源。演示结束后，将开关恢复为 `False`，避免意外重复请求。

实时请求会消耗服务提供方额度；OpenAI推理会产生API用量。搜索结果可能没有天气answer box。遇到这种情况，应说明失败，而不是填入猜测值。SerpApi提供的是Google天气搜索结果；只有结果明确标识上游信息发布方时，才能给出其名称。数据获取时间不等于天气观测时间。

### 从最先失败的位置开始排查

| 现象 | 下一步操作 |
|---|---|
| `LAB`、`run_lab` 或 `PYTHON` 未定义 | 按顺序运行Preparation A、B、C、D |
| 包导入／安装失败 | 重新运行B；安装仍失败时向讲师求助 |
| 添加密钥后未选中OpenAI模式 | 允许笔记本访问该密钥，然后重新运行C |
| 模型身份验证／额度错误 | 避免投屏，私下检查账号与密钥；未解决则使用备用模式 |
| 找不到模型 | 请讲师核实配置的模型ID与访问权限 |
| MCP启动或工具发现失败 | 重新运行D；先检查准备状态，再尝试模型推理 |
| 没有可用的天气结果 | 检查城市、国家和返回错误，不要猜测天气 |
| 运行时被替换或连接断开 | 重新连接并执行准备步骤，从已保存的笔记本恢复笔记 |
